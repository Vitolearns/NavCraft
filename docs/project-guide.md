# 设计取舍与演示验证

NavCraft 将已有地图导航、建图和独立路径跟踪分为三种互斥模式。默认导航在复杂仓库中使用 AMCL 和 Nav2；任务执行、速度保护和进程管理由项目自身模块完成。

## 模块分工

| 设计 | 实现 | 验证方式 |
|---|---|---|
| 有限航点任务 | navcraft_mission 异步状态机，处理占用、暂停、取消与迟到回调 | test_executor.py 故障注入；Gazebo 停车与恢复 |
| 导航速度保护 | navcraft_safety 检查单调时钟超时、状态、急停和限幅 | 故障测试与实际停车观测 |
| 控制链隔离 | 互斥 launch、ROS 域锁与子进程回收 | 生命周期测试及唯一最终速度发布者检查 |
| 仓库导航 | 匹配地图、初始位姿、六站路线、实体障碍和 RViz | 障碍入图、重规划、世界坐标到站核验 |
| 独立跟踪 | Pure Pursuit / Stanley、误差采样与 CSV/JSON 导出 | 给定路径上的运动、急停与误差记录 |
| 底盘适配 | backend、Serial/UDP、mock、ros2_control | 协议单元测试与软件模拟 |

Nav2 提供定位、规划、局部控制与恢复行为。独立 PP/Stanley 节点用于给定路径的跟踪实验，与 Nav2 的 Regulated Pure Pursuit 插件分别运行；独立跟踪不包含全局规划或激光避障。

## 数据与测量

默认导航使用激光、轮式里程计和 TF。IMU 与相机提供独立数据流，未接入默认导航融合；EKF 作为可选底盘入口提供，融合精度尚未评估。

仓库验收通过独立世界位姿核对实际到站与绕障距离。世界位姿不输入导航定位，地图定位和轮式里程计分别记录。当前轮式里程计偏差见 [验收记录](validation.md)。

## 演示顺序

1. 启动 Gazebo 与 RViz，核对激光、定位、全局路径和代价地图。
2. 提交六站任务，观察货架通道中的路径规划与跟随。
3. 放置实体障碍，观察感知入图、路径变化和机器人实际绕行。
4. 行驶中暂停、恢复和取消，观察任务状态与实际停车。
5. 关闭导航后，按需启动独立跟踪或建图模式。

操作命令见 [仓库演示](warehouse-demo.md) 和 [维护文档](development.md)。自动验收用于复现指定路线、障碍注入时机和到站判据。

## 验证范围

验收覆盖仿真与软件 mock。OccupancyGrid 生成检查不包含完整建图精度评估，跟踪运动检查不构成算法性能排名。门、电梯与充电桩属于场景装饰。实际执行日期、结果和未验证项统一记录在 [validation.md](validation.md)。
